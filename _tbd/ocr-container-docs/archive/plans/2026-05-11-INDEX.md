## Cross-plan invariants

All six plans share these constraints:

1. **Workspace memory is canonical.** `~/.claude/projects/-workspaces-ocr-container/memory/MEMORY.md` is the user's; per-agent memory lives under `/workspaces/ocr-container/.claude/agent-memory/<agent>/`. Never write memory into a `pd-*/` tree (leakage check per CLAUDE.md).
2. **Delegate in-repo code changes** to the matching `pd-<repo>` agent per CLAUDE.md routing. Workspace-level glue (label seeding, ctask entries, `scripts/*`) is fine from the orchestrator.
3. **Use `uv run`**, not direct `python3`/`pytest` — per workspace memory (`feedback_use_uv_not_python3.md`).
4. **No `--no-verify` / `--no-gpg-sign`** on commits — pre-commit hooks are the source of truth (workspace memory `feedback_pre_commit_no_skip.md`).
5. **`/srv/bot-workspaces/` quirks:**
   - Owned by `claude-bot` (uid 1001); vscode (uid 1000) reads only via `safe.directory` config.
   - Any edit-then-commit cycle inside a bot worktree must run as `sudo -u claude-bot ...` (workspace-rc finding).
   - Pre-commit's `pre-commit install` is skipped in worktrees (`.git` is a file, not a dir); run `make lint` directly.
6. **Spec-issue/feature-request convention** — already in flight per workspace-rc:
   - `kind:feature-request` issue is filed first
   - `/triage` either rejects or forks a `kind:spec` child issue
   - `/spec-from-issue <N>` writes the design spec + creates draft PR
   - `/decompose-spec <path>` creates per-spec milestone + child issues with `bot:ship-issue-ready`
7. **All assistants should batch-commit per-task** (TDD slice) with conventional commit messages — no monster commits.
